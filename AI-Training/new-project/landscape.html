Concept 1

AI, platforms, and models — three different things

Before we get into how AI works, it helps to get oriented on the landscape — who's making these tools, what they're actually called, and why the naming is so confusing.

🔌

AI is electricity. The platform is the appliance. The model is what's inside the appliance that makes it actually work.

These three words get used interchangeably, but they mean different things.

AI is the broad capability — the underlying technology that can understand and generate language. Think of it like electricity. Electricity itself isn't a product; it's what powers products.

A platform is the product you actually use — the interface, the app, the thing you log into. ChatGPT is a platform. Claude.ai is a platform. They're the appliances plugged into the electricity.

A model is the specific engine running inside the platform — the trained system doing the actual thinking. This is where names like GPT-4o or Claude Sonnet come from. They're not products you buy; they're engines that power products.

Why it matters Why does this matter? Because when someone says "I use Claude," they mean the platform. When they say "I'm using Sonnet," they mean the model running inside it. And when they say "this is powered by AI," they mean the broad capability — which tells you almost nothing useful.

The Copilot exception — why it's confusing
🚗

Copilot is Microsoft's car with OpenAI's engine inside.

Microsoft makes the platform. But Microsoft doesn't make the model. Copilot runs on OpenAI's GPT models under the hood — Microsoft licensed the engine and built the car around it.

This is why Copilot feels similar to ChatGPT in some ways — they're running the same engine, just with different interfaces and different integrations. Copilot plugs into Office, Teams, and Windows. ChatGPT stands alone.

Concept 3

What model versions actually mean

🐎

Model versions are like horsepower ratings. More isn't always what you need — it depends on what you're trying to do.

When you see names like Haiku, Sonnet, Opus — or GPT-4o, GPT-4, GPT-3.5 — they're describing different versions within the same model family. Each version makes different tradeoffs.

Within the Claude family

Haiku

Fastest, cheapest, handles simple tasks well.

Best for: quick questions, high-volume tasks

Sonnet

The middle ground — capable and efficient.

Best for: most everyday work, coding, writing

Opus

Most capable, slowest, most expensive.

Best for: complex reasoning, nuanced tasks

The takeaway Think of it like coffee sizes, except instead of small/medium/large the tradeoffs are speed, cost, and capability — and bigger isn't always better. If you need a quick answer to a simple question, Haiku will get you there faster and cheaper than Opus would.

Concept 4

What is an API?

You'll hear this word constantly and it's simpler than it sounds.

🧑‍🍳

An API is like a waiter. You don't go into the kitchen yourself. You tell the waiter what you want, the kitchen makes it, and the waiter brings it back.

API stands for Application Programming Interface — but forget the acronym. Here's what it actually means.

An API is a way for one piece of software to talk to another. When a product says it's "powered by Claude" or "uses GPT-4," they built their product by connecting to Anthropic's or OpenAI's API. They're not running the model themselves — they're sending requests to it and getting responses back.

For designers For designers, the practical implication is this: when you use Claude.ai, you're using Anthropic's own interface. When you use a design tool that has AI built in — like Figma's AI features — that tool is probably talking to a model via API behind the scenes. Same model, different interface.

Concept 5

What is an agent?

This one is newer and you'll hear it more and more.

📋

A regular AI interaction is like asking someone a question. An agent is like delegating a task.

Most AI interactions are reactive — you ask, it answers. An agent is different. An agent is an AI that can take a sequence of actions on its own to accomplish a goal, not just respond to a single prompt.

Regular AI interaction

You: "Write me a research plan for this project."

AI: [writes the research plan]

Done.

Agent

You: "Research this topic and summarize the key findings for me."

Agent: searches the web → reads sources → synthesizes findings → writes summary → flags anything that needs your review

Done — but it did several steps on its own.

For designers For designers, agents are starting to matter because tools like Claude Code operate more like agents — you give them a goal, and they take a series of steps to get there, rather than just answering a single question.

Concept 6

What is a CLAUDE.md?

This one is specific to working with Claude Code, but worth knowing because you'll see it referenced in engineering conversations.

📄

Think of CLAUDE.md like an onboarding doc you wrote for a new team member — except the team member reads it perfectly every single time and never forgets it.

A CLAUDE.md is a file you create in your project that gives Claude persistent instructions. Instead of explaining your project's rules and preferences every single conversation, you write them down once in a CLAUDE.md file and Claude reads it automatically every time it works in that project.

For designers For designers working with Claude Code, this is the practical implication: the more you encode your team's standards and knowledge into files like CLAUDE.md, the less you have to re-explain context every session. Your preferences become infrastructure.
