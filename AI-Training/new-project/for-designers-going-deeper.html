This section is for designers who have been handed a new AI tool and told to "just use it" — and weren't sure where to start.

We'll cover which tool to reach for and when, how to get started with Figma AI, and how to use Claude Code without needing an engineering background.

Which tool for what

You may have access to several AI tools and no clear guidance on which to use for what. Here's the honest breakdown for your stack.

Claude Code

Made by Anthropic

Building tools, prototypes, and structured projects that need to exist as real files. Works directly in your file system. Highest learning curve of the tools in this guide — also the highest capability ceiling.

Reach for it when: You need to build something, not just draft it.

Claude.ai

Made by Anthropic

Writing, synthesis, research readouts, artifact drafts. Conversational interface — no file system, no setup. Where to start for most design research tasks.

Reach for it when: You have data to synthesize or content to draft and you want to stay in a chat interface.

Copilot

Made by Microsoft (OpenAI engine)

Tasks you're already doing in Microsoft 365 — Word, PowerPoint, Teams, Outlook, Excel. Analyzing support tickets in Excel is a strong use case.

Reach for it when: You're already in a Microsoft tool and don't want to switch contexts.

Figma AI

Made by Figma

Design-specific tasks that would otherwise require leaving Figma — writing copy on a frame, generating variations, getting layout suggestions. Still maturing — results vary.

Reach for it when: You're already in Figma and the task is design-specific.

GenAI Studio

Made by Google

Multimodal tasks — inputs that combine images, audio, and text. More technical interface than the other tools in this list — designed for developers but usable by designers willing to explore.

Reach for it when: You're working with inputs that aren't just text, or you want to experiment with capabilities beyond chat.

Task routing — reach for:

Draft a research readout from transcripts→Claude.ai
Analyze support tickets→Copilot (in Excel) or Claude.ai
Build an interactive prototype or tool→Claude Code
Write UX copy inside a design file→Figma AI
Synthesize interview notes→Claude.ai
Generate a persona draft→Claude.ai
Pressure-test a journey map→Claude.ai
Experiment with image or multimodal input→GenAI Studio
Build something that needs to live as a file or be shared as a link→Claude Code

Figma AI — what it is and how to think about it

Figma AI is different from the other tools in this guide in one important way: it lives inside Figma. You don't switch tabs, paste content somewhere else, or translate between a design file and a chat interface. The AI assistance happens in context — while you're looking at your actual designs.

🎨

Figma AI is like having a design assistant sitting next to you while you work — available when you need it, ignorable when you don't. The value is that it's already in the room.

What that makes it good for

Tasks where leaving Figma creates friction.

Writing and rewriting copy directly on a frame — error states, button labels, onboarding text — without copying it out and back in.

Generating layer variations without breaking your workflow.

Getting a first pass at auto-layout or component suggestions while you're already in the file.

What it doesn't replace

Claude.ai or ChatGPT for research and synthesis work — Figma AI is a design tool, not a research tool.

Claude Code for building anything that needs to exist outside of Figma.

Your own design judgment — Figma AI generates options, you decide what's right.

The honest state of it

Figma AI is still maturing. Some features work well. Some are inconsistent. The interface changes frequently as Figma ships updates.

The best way to learn it right now is to open a low-stakes file and try the things that show up — right-click menus, the toolbar, and the AI panel if it's available in your plan.

For current feature documentation, go to Figma's own docs — they'll always be more up to date than anything written here.

What it actually is

Claude Code is different from Claude.ai — the chat interface you might use for writing or research. Claude Code is an AI that works directly with files on your computer. It can create files, write code, build things, and make changes across an entire project at once.

Claude.ai

You have a conversation.

It writes things for you.

You copy what you need.

Claude Code

You give it a project.

It builds things for you.

It works in your actual files.

For designers For designers, this means you can use Claude Code to build prototypes, create simple tools, or — as this site demonstrates — build an entire interactive website by briefing it the way you'd brief a developer.

Where projects live — understanding the file system

When Claude Code creates a project, it creates a folder on your computer. But where that folder ends up depends on where your terminal is currently pointed — and that's not always obvious.

📍

The terminal has a location, like a cursor in Finder. Wherever it's pointed is where new things get created.

How to know where you are:

Type: pwd — That stands for "print working directory." It shows your current location — something like /Users/yourname/Documents

How to avoid losing your projects:

1Create a dedicated folder for AI projects somewhere you'll remember — Desktop or Documents works well. Name it something clear: "AI Projects" or "Claude Projects."
2When you start a new Claude Code session, tell it where to put the project: "Create this project in /Users/[yourname]/Documents/AI-Projects/"
3Now you always know where your work lives — no hunting through Finder wondering where things went.

Git and repos — what they are and why they matter

When Claude Code asks to initialize a repository or runs git commands, here's what's actually happening.

🗂️

A repository is a project folder with a memory. A regular folder holds your files. A repo holds your files AND a complete history of every change ever made — who changed what, when, and why.

That history is managed by a tool called Git. Git is not the same as GitHub — a common point of confusion:

Git

A tool that runs on your computer.

Tracks changes to files locally.

The technology itself.

GitHub / GitLab

Websites that store your repo in the cloud so others can access it and collaborate.

Think of it like Google Drive — but specifically for code.

📑

Git is like track changes in a document — except it works across every file in your project simultaneously, never forgets anything, and you control exactly when a version gets saved.

Git commandWhat it does
git initTurns a regular folder into a repo — starts tracking changes. Usually happens once at the start of a project.
git addTells Git which files to include in your next snapshot. Like selecting files before you back them up.
git commitTakes the snapshot. Creates a saved point in history you can return to. Usually includes a message describing what changed.
git pushSends your local snapshots to GitHub or GitLab so they're backed up and others can see them.
git pullBrings down changes others made from the cloud to your local files.
git statusShows what's changed since your last snapshot. Good to run when you're not sure what's happened.
git logShows the full history of all your snapshots. Like a changelog.

Bash commands — a designer's field guide

When Claude Code wants to do something on your computer — create a folder, install a dependency, run a local server — it asks permission first. That request is a bash command.

Bash is just a way of talking directly to your computer through text. The commands look technical but most of them are doing simple things.

🛠️

Approving a bash command is like approving a contractor to do work in your house. You don't need to know how to do the work yourself — but you should know whether they're painting a wall or knocking one down.

The two approval options — what they actually mean

"Yes, just this once"

Approve this specific command. Claude Code will ask again next time.

Right choice when: you don't recognize the command, or you're early in a session and still getting oriented.

"Yes, don't ask again"

Auto-approve all commands in this session. Claude Code runs what it needs to without checking in.

Right choice when: you're deep in a working session, you understand what's being built, and the project is self-contained with nothing important at risk.

Tip When in doubt, type this before approving: "What does this command do, in plain english?" Claude Code will explain it. You're never required to approve something you don't understand.

How to write a brief Claude Code can execute

This site is the proof of concept. The brief used to build it — clear layers, approved copy, specific interaction notes, visual tone references — is the template for any Claude Code project.

  • Establish context before requirements

    Tell Claude Code what this is and who it's for before telling it what to build. It makes better decisions when it understands the purpose.

  • Be specific about interactions

    "Make it interactive" is not a brief. "Show a stepped click-through where each click reveals one concept" is. The more precisely you describe the behavior, the less Claude Code has to invent.

  • Separate your copy from its copy

    Provide approved content verbatim and tell Claude Code not to rewrite it. Let it generate only what you haven't written — then review that separately.

  • Propose before building

    Ask Claude Code to describe its approach before it executes. "Show me two or three options before you build anything" keeps you in the design seat.

  • Scope narrowly and iterate

    Don't hand Claude Code everything at once. Build one section, review it, then expand. Rebuilding is harder than iterating.

The gofer problem — and how to reduce it

If you've found yourself copying output from one AI tool and pasting it into another, you've experienced what we'd call the gofer problem. You're acting as a human connector between tools that don't talk to each other natively.

This happens because different tools have different strengths — and right now they don't communicate automatically. The routing guide earlier in this section is the first step to reducing it: be intentional about which tool you're using and why, rather than ending up in multiple tools without meaning to.

  • Consolidate where possible

    If you're building something in Claude Code, try to do as much as possible in that session. Give Claude Code the brief AND ask it to generate the content — the way this site was built.

  • Be intentional when you do switch

    "I'm going to Claude.ai for a fast first draft I'll bring back here" is a deliberate choice. Accidentally ending up in three tools because you didn't know you could do it in one is friction that adds up.

  • Use CLAUDE.md to reduce context loss

    The more your project preferences and standards live in a CLAUDE.md file, the less you have to re-paste context from other tools every session. Your brief becomes infrastructure.
