Concept 4

What is an API?

You'll hear this word constantly and it's simpler than it sounds.

🧑‍🍳

An API is like a waiter. You don't go into the kitchen yourself. You tell the waiter what you want, the kitchen makes it, and the waiter brings it back.

API stands for Application Programming Interface — but forget the acronym. Here's what it actually means.

An API is a way for one piece of software to talk to another. When a product says it's "powered by Claude" or "uses GPT-4," they built their product by connecting to Anthropic's or OpenAI's API. They're not running the model themselves — they're sending requests to it and getting responses back.

For designers For designers, the practical implication is this: when you use Claude.ai, you're using Anthropic's own interface. When you use a design tool that has AI built in — like Figma's AI features — that tool is probably talking to a model via API behind the scenes. Same model, different interface.

Concept 5

What is an agent?

This one is newer and you'll hear it more and more.

📋

A regular AI interaction is like asking someone a question. An agent is like delegating a task.

Most AI interactions are reactive — you ask, it answers. An agent is different. An agent is an AI that can take a sequence of actions on its own to accomplish a goal, not just respond to a single prompt.

Regular AI interaction

You: "Write me a research plan for this project."

AI: [writes the research plan]

Done.

Agent

You: "Research this topic and summarize the key findings for me."

Agent: searches the web → reads sources → synthesizes findings → writes summary → flags anything that needs your review

Done — but it did several steps on its own.

For designers For designers, agents are starting to matter because tools like Claude Code operate more like agents — you give them a goal, and they take a series of steps to get there, rather than just answering a single question.

Concept 6

What is a CLAUDE.md?

This one is specific to working with Claude Code, but worth knowing because you'll see it referenced in engineering conversations.

📄

Think of CLAUDE.md like an onboarding doc you wrote for a new team member — except the team member reads it perfectly every single time and never forgets it.

A CLAUDE.md is a file you create in your project that gives Claude persistent instructions. Instead of explaining your project's rules and preferences every single conversation, you write them down once in a CLAUDE.md file and Claude reads it automatically every time it works in that project.

For designers For designers working with Claude Code, this is the practical implication: the more you encode your team's standards and knowledge into files like CLAUDE.md, the less you have to re-explain context every session. Your preferences become infrastructure.
